# Database Component with passwordless mTLS and SCRAM admin

Propraetor needs a shared relational database for Workloads that should not invent per-Workload passwords or treat Service Network basename DNS as authentication. **Database** is a mandatory public-Host Component (idle allowed with zero claimants): Postgres on the Service Network at dial name `database` (Workload basename `database` fail closed); Host Volume SoT under `data/components/database/` (CA, server cert, per-basename client material, `pgdata`). A Workload Declares need via Manifest `"database": true` (ADR-0024 allowlist thicken). Database Component Setup gathers Intent-**run** claims only: create-if-missing role+database named by basename, issue client cert CN=`basename`, map via `pg_ident`, `pg_hba` `hostssl … cert clientcert=verify-full` for Workloads; publish binding under `~/.config/platform/workloads/<basename>/database/` (certs + connection env, no password) with a Setup-owned Quadlet drop-in — Component Setup owns the projection. Intent `stop`/`trash` unpublishes; **Purge** / **Orphan Reap** drop role, database, and client material (refresh in `post-workloads`; create/publish prefer `pre-workloads` so bindings exist before app start). Schema/migrations stay Workload-owned; no cross-Workload grants in v1. Admin path is dual `pg_hba`: SCRAM for Environment-scoped **Database admin credentials** (`ROOT_DB_USER`, `ROOT_DB_PASSWORD`) staged from `environments/<slug>/.env` (or shell) into Component interior — same file as Environment Configuration may hold them, but they are **not** the Workload bag (never Manifest `environment`; ensure-components stages them). Operator UI `./database.sh [read|write]` (`read` default; `--env` as usual; no workload/dbname in v1) opens `psql` via SSH TCP tunnel as that admin role; `read` sets soft `default_transaction_read_only` (documented bypassable). Same-operator co-tenant limits remain ADR-0034. In-pod teaching (`web-api-with-db`) stays; a separate Component teaching example is later. Deferred: cert rotation UX, backups as Component feature, footprint knobs beyond small-Host defaults.

**Amends:** ADR-0024 (Manifest may include boolean `database`); ADR-0035 (reserved `ROOT_DB_USER` / `ROOT_DB_PASSWORD` are Database admin credentials extracted from the Environment `.env`/shell — not Workload Environment Configuration; Components still do not consume the Workload bag); ADR-0040 / ADR-0043 (Database is a second Declaration-fulfilling Component; slot bodies Component-owned — fulfillment/publish in `pre-workloads`, Purge/orphan cleanup in `post-workloads`).

**Rejected:** Network `trust`, hostname/`NetworkAlias` auth, Unix `peer`, IP allowlists; storing generated Workload DB passwords on the Host Volume; Manifest-held DB secrets; Operator Configuration for admin creds (cross-Environment coupling); bind-mounting Workloads into Component interior as the supported publish path; retain-DB-on-Purge; optional/absent Database Component when Manifest claims `database`; hard RO admin role split for v1 `database.sh read`.

**Day-to-day truth:** `CONTEXT.md` (**Database**, **Database admin credentials**, Manifest / Declaration / Purge).
