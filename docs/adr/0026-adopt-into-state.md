# Adopt allowlisted provider facts into State during lifecycle commands

Amends ADR-0025’s operator convergence promise. Apply, Park, and Teardown must still converge by repeating the same normal operator command and must never require the operator to run imports, edit State, use targets, or perform provider-console surgery. Lifecycle commands may **Adopt**: bind an already-existing provider fact into State under the Environment’s known Stack-owned identity. Adopt always starts with preflight before the plan.

Adopt is allowlisted and exact-match only. Apply may Adopt identity-stable Durables (Domain, Host Volume, Cloud Project, Durable memberships) and known Recreatable relationships whose endpoints are already known (e.g. Reserved IP assignment when the IP and Host are in State). Park and Teardown may Adopt allowlisted Durables and Durable relationships only — not Recreatable presence. Ambiguity, wrong endpoint, identity conflict, unbound Host discovery, and orphan Reserved IP addresses (no Environment key without State) fail closed. Reactive Adopt after a failed apply is out of scope until evidence requires it.

There are two binding mechanisms behind the same Adopt interface:

1. **Pre-plan binding.** When the Terraform resource supports import, preflight validates the provider identity and endpoints, then imports the fact before the complete plan.
2. **Provider-native self-binding.** DigitalOcean provider v2.95.0 does not support import for `digitalocean_project_resources` or `digitalocean_volume_attachment`. Preflight may validate an exact relationship and let the ensuing complete Apply or Park apply show its State-missing owner as `create` only when the provider Create handler is known to leave that exact provider fact unchanged and merely record the owner in State. Live evidence confirms this for `module.recreatables[0].digitalocean_project_resources.web_host`, `module.recreatables[0].digitalocean_volume_attachment.web`, and `module.durables.digitalocean_project_resources.durables` while the Reserved IP is unassigned. If a relationship points to a different Host or non-default Cloud Project, preflight fails before the plan. A relationship absent at the provider is ordinary convergence, not Adopt, and may be created normally.

Provider-native self-binding is deliberately narrow. It is not permission to treat arbitrary idempotent creates as Adopt, to use targets, or to accept a plan that moves an existing relationship. In particular, it is **not safe** for `module.durables.digitalocean_project_resources.durables`: even when every membership is already exact, its Create handler POSTs the complete set, and DigitalOcean rejects an included attached Reserved IP with HTTP 412 (“Cannot move a Reserved IP with an associated Droplet”). That State gap fails closed rather than claiming self-binding. Teardown never runs provider-native Create: it adopts import-capable endpoints, and deleting those endpoints removes non-importable relationships with them. The allowlist and exact endpoint proof remain mandatory, and repeating the same lifecycle command must still end with an empty plan.

Live test-Environment evidence for the safe Applied cases removed only the Host membership and Host Volume attachment owners from State while retaining their provider facts. Repeating ordinary Apply reported both provider-native Adopts, created two State owners without changing endpoints, and the immediate complete follow-up plan was empty. For the safe Parked case, ordinary Park first removed Recreatables and unassigned the Reserved IP; removing only the exact Durable membership owner and repeating Park self-bound it, and the next Park was empty. Apply then restored the Stack and an immediate complete plan was empty. The equivalent Durable-membership fixture while Applied produced the HTTP 412 above and was restored without provider change; it is the external State-loss case tracked in #67, not evidence of Adopt.

This replaces Domain “name already exists → manual import runbook” as the normal path for declared Domains. One-shot surgery remains only for non-allowlisted orphans.

## Considered

Fail-closed forever on provider-has/State-missing (forces manual import; breaks hands-off Park→Apply when the provider flakes). Reactive-only Adopt without preflight (misses quiet gaps; still leaves “already assigned” traps unless failure parsing is perfect). Auto-Adopt of orphan Reserved IPs by region (unsafe identity). Handcrafted State insertion or internal targeted applies for non-importable relationships (routine State surgery and incomplete plans). Rejected for now.
