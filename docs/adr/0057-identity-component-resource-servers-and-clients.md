# Identity Component gathers resource servers, OIDC clients, and permission grants

Public APIs Bound on a Domain need user-delegated access tokens from a Host-local Identity Provider; co-tenant Workloads on the Service Network do not (ADR-0034). **Identity** is a mandatory public-Host Component (peer of Edge, Database, Cache; idles with zero claimants). `identity.json` is required for every Environment — missing file fails closed at Deploy; the file must contain exactly one want-list FQDN (no placeholder state). Identity admin credentials are mandatory for every Environment. Engine is Pocket ID. Service Network dial name `identity` (Workload basename `identity` is rejected, peer of `database` / `cache`). Propraetor does not invent a second authorization server. Edge stays TLS, ACME, Routes, and Forwarded client identity (ADR-0052) — **not** the JWT verifier. The API Workload verifies Bearer **access** tokens (JWKS, `iss`, `aud`, expiry, permission key in `scope`). Bound ≠ resource server: a site or SPA must load without a Bearer.

**Issuer hostname** is declared in committed `environments/<slug>/identity.json` — an Environment-authored Declaration (peer of `domains.json` / `acme.json`). The file is required for every Environment — missing file fails closed at Deploy. Must contain exactly one want-list FQDN (no placeholder state); fail closed if the FQDN is not on the Domain want-list. `ensure-components` stages the file onto the Host alongside the ACME want-list and admin credentials. Edge owns the Domain front for that FQDN and includes an Edge-owned proxy block to the Identity Service Network dial name — not a Workload Route. Edge `post-workloads` fails closed if any Workload Binding attaches Routes to the Identity-claimed FQDN; that Domain front carries only the Edge baseline and the Identity proxy. Changing the issuer hostname is a WebAuthn RP ID change (every passkey breaks) — treat it as effectively immutable. The environment-scoped Pocket ID `resource` (the JWT `aud`) used for Workload permission catalogs is `propreator:${env-slug}` and must not equal the issuer FQDN (Pocket ID rejects `resource` = issuer).

A Workload is an Identity claimant only with **Requires** `"identity": true` (peer of `database` / `cache`; ADR-0053). **API permission catalog:** non-empty **Provides** `permissions` (key → human name; key is the OAuth scope token) contributes to the Environment-scoped Pocket ID audience (`aud = propreator:${env-slug}`). For API-level access control, the operator must include the mandatory per-API marker permission key `${workload-slug}:api` in this Workload’s `permissions` map; all other keys in `permissions` must follow the convention `${workload-slug}:${permission}` (where `${permission}` is the operator-chosen capability identifier). The API authorization layer enforces access by requiring the `${workload-slug}:api` marker key to be present in the token `scope` (in addition to any other API-specific scopes). Propraetor only constrains issued tokens by requested scope keys; API-side authz must enforce the marker key. **OIDC client:** **Requires** `permissions` (same shape) plus **Provides** `"oidc_callback": "/…"` (value is the path). Required keys may span multiple APIs; user consent is per permission key set, and an API accepts a token only when it includes that API’s `${workload-slug}:api` marker key. Client Binding may list many FQDNs; each callback URL is `https://<fqdn>` plus that path. Zero client FQDNs fails closed. Same Workload may be both (Required keys ⊆ own catalog). `identity` with neither catalog nor client keys fails closed. No permissions map on Binding. No logout callback URLs. User groups / client allow-list in the Identity Provider UI are not gathered.

**Identity admin credentials** are Environment-scoped operator-supplied secrets staged by `ensure-components` as Pocket ID environment variables (peer of Database/Cache admin credentials — not Environment Configuration, never Binding-remapped into Workloads): **`ROOT_IDENTITY_API_KEY`** (≥ 16 chars; staged as Pocket ID `STATIC_API_KEY` — grants admin API access via `X-API-Key` header; creates a synthetic admin user excluded from the real-user count); **`ROOT_IDENTITY_ENCRYPTION_KEY`** (staged as Pocket ID's encryption key — lost key means unreadable SQLite after rebuild); **`ROOT_IDENTITY_ADMIN_EMAIL`** (mandatory; consumed only on first deploy — Setup detects zero real users via `GET /api/signup/setup` → 204, creates an admin user with this email via `POST /api/users`, generates a one-time access token via `POST /api/users/:id/one-time-access-token`, and prints the login URL `https://<fqdn>/lc/{token}` — the operator opens it to add a passkey; this also permanently blocks Pocket ID's unauthenticated `/setup` endpoint). **`APP_URL`** is not operator-supplied — `ensure-components` derives it as `https://<fqdn>` from `identity.json`.

**Ownership.** Propraetor owns Identity infrastructure objects it creates by known Workload identity — catalogs (by resource URI), OIDC clients (by basename), and api-access grants — full-replace on every Deploy. The operator owns Identity data: users, passkeys, groups, and any UI-created objects whose ID is not a Workload basename or resource URI (Setup never deletes unrecognized objects). UI edits to gathered objects are **Escape Hatch** — unsupported, overwritten on next Deploy, no compatibility promise. Create-or-update silently takes over a UI-created object if its ID matches a Workload basename or resource URI (no collision guard).

**Gather (Component Setup).** Intent-**run**: upsert Pocket ID API by `resource` (`POST` / list+match; `resource` unique and immutable); `PUT` permissions as a full replace that matches by **key** (UUID stable if the key stays); create-or-update a **public + PKCE** OIDC client by `GET /api/oidc/clients/:id` with `id` = Workload basename (404 → `POST` create, 200 → `PUT` full-replace update; `id` immutable after create; duplicate → 409; Workload basename characters are within the Pocket ID client-ID charset `[a-zA-Z0-9._-]{2,128}`); group restriction explicitly `false` (API default; the UI defaults to `true` — Setup must be explicit); `PUT` api-access with permission UUIDs resolved from keys; publish Component-owned bindings under `~/.config/platform/workloads/<basename>/identity/` (not Binding remaps) — resource server: issuer, JWKS URL, `aud`; client: issuer, `client_id`, callback URLs, `resource`, `scope` (gathered permission keys only — standard OIDC scopes `openid`, `profile`, `email`, `groups`, `offline_access` are engine-provided on every client and not gathered or published by Setup). Intent **stop** unpublishes that binding and **leaves** Identity interior records (minting while the Workload is down is accepted). Omit Provides `permissions` (still Bound as a site), omit the client Declaration, Binding FQDN gone, or **Orphan Reap**: delete the corresponding Pocket ID API and/or OIDC client. Tokens already minted keep old `scope` strings until `exp`; delete does not revoke. Identity admin API material is Component admin material (not Environment Configuration). Slot bodies follow Database (ADR-0049 / ADR-0043): fulfillment/publish prefer `pre-workloads`; orphan cleanup in `post-workloads`.

**Amends:** ADR-0053 (Provides gains `permissions` and `oidc_callback`; Requires gains `identity` and optional client `permissions`; Binding no longer determines token audience/resource for permission catalogs — Identity audience is Environment-scoped); ADR-0040 / ADR-0043 (Identity is a further Declaration-fulfilling Component; Environment-authored issuer hostname beside Domain assignment); ADR-0034 (Service Network stays token-free; this story is public Bound APIs and SPAs only); ADR-0052 (Edge is not the JWT gate).

**Rejected:** Partial UI ownership of gathered object fields (merge-on-update adds read-modify-write races and splits SoT); deleting unrecognized Pocket ID objects (breaks operator UI-created clients/catalogs); collision guard on ID match (Pocket ID doesn't expose creator — keep create-or-update simple); Identity as optional / demand-driven Component (mandatory product bit — peer of Edge, Database, Cache; `identity.json` required, no "absent = idles" state); Edge JWT verification (option 3); Hydra / Dex as this Identity Provider; inferring a resource server from Bound Routes; one Pocket ID API per alias FQDN; per-key or `*` permission Binding; clients named on the resource-server Artifact; globally unique keys without API-specific marker permission keys; delete catalog/client on Intent **stop**; surgical permission HTTP (Pocket ID only offers full replace-by-key); CIMD or Pocket ID UI as v1 client registration; logout callback gather; user groups; Requires boolean `oidc`; convention issuer hostname (in `domains.json` or inferred); Identity as a Workload; Identity publishing Routes through the Workload Route channel (Components should not fake being Workloads — ADR-0040); magic `/callback` path; client secrets / `client_credentials` for Service Network; gather-time token revocation; UI-minted rotatable `X-API-Key` as Setup's auth (chicken-and-egg — requires a logged-in admin to create); Pocket ID `/setup` endpoint for first-human bootstrap (unauthenticated race window on public FQDN); Setup-generated encryption key stored in Persist (operator cannot back it up independently); operator-supplied `APP_URL` (derivable from `identity.json`, drift risk); deferring first-admin creation to a separate operator tool (adds a human gate on first deploy); optional `ROOT_IDENTITY_ADMIN_EMAIL` (simpler to always require it).

**Deferred:** Confidential clients (`client_secret`, server-side authorization-code and `client_credentials` flows) — not gathered today; the only token consumers are browsers (public + PKCE) and co-tenant Workloads use the token-free Service Network. Needed when an external API consumer outside the Service Network requires server-to-server user-delegated or machine-to-machine tokens. Client access is constrained by requested permission keys (including per-API marker keys), not by a per-resource-server audience.
