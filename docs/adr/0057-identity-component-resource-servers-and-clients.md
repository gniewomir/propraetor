# Identity Component gathers resource servers, OIDC clients, and permission grants

Public APIs Bound on a Domain need user-delegated access tokens from a Host-local Identity Provider; co-tenant Workloads on the Service Network do not (ADR-0034). **Identity** is a public-Host Component (idle allowed with zero claimants). Engine is Pocket ID. Service Network dial name `identity` (Workload basename `identity` is rejected, peer of `database` / `cache`). Propraetor does not invent a second authorization server. Edge stays TLS, ACME, Routes, and Forwarded client identity (ADR-0052) — **not** the JWT verifier. The API Workload verifies Bearer **access** tokens (JWKS, `iss`, `aud`, expiry, permission key in `scope`). Bound ≠ resource server: a site or SPA must load without a Bearer.

**Issuer hostname** is declared in committed `environments/<slug>/identity.json` — an Environment-authored Declaration (peer of `domains.json` / `acme.json`). The file names exactly one want-list FQDN; missing file means no Identity issuer for that Environment (Identity idles). Fail closed if the FQDN is not on the Domain want-list. `ensure-components` stages the file onto the Host alongside the ACME want-list and admin credentials. Edge owns the Domain front for that FQDN and includes an Edge-owned proxy block to the Identity Service Network dial name — not a Workload Route. Edge `post-workloads` fails closed if any Workload Binding attaches Routes to the Identity-claimed FQDN; that Domain front carries only the Edge baseline and the Identity proxy. Changing the issuer hostname is a WebAuthn RP ID change (every passkey breaks) — treat it as effectively immutable. The resource URI `https://<fqdn>` for a Workload's Provides `permissions` must not equal the issuer FQDN (Pocket ID rejects `resource` = issuer).

A Workload is an Identity claimant only with **Requires** `"identity": true` (peer of `database` / `cache`; ADR-0053). **Resource server:** non-empty **Provides** `permissions` (key → human name; key is the OAuth scope token). Exactly **one** Binding FQDN; `resource` / JWT `aud` is `https://<fqdn>` (no path, trailing slash trimmed). Zero or two+ FQDNs with a catalog fails closed. Permission keys must be unique across Workloads. **OIDC client:** **Requires** `permissions` (same shape) plus **Provides** `"oidc_callback": "/…"` (value is the path). Required keys must all belong to exactly one resource-server catalog; spanning two catalogs fails closed. Client Binding may list many FQDNs; each callback URL is `https://<fqdn>` plus that path. Zero client FQDNs fails closed. Same Workload may be both (Required keys ⊆ own catalog). `identity` with neither catalog nor client keys fails closed. No permissions map on Binding. No logout callback URLs. User groups / client allow-list in the Identity Provider UI are not gathered.

**Gather (Component Setup).** Intent-**run**: upsert Pocket ID API by `resource` (`POST` / list+match; `resource` unique and immutable); `PUT` permissions as a full replace that matches by **key** (UUID stable if the key stays); create-or-update a **public + PKCE** OIDC client by `GET /api/oidc/clients/:id` with `id` = Workload basename (404 → `POST` create, 200 → `PUT` full-replace update; `id` immutable after create; duplicate → 409; Workload basename characters are within the Pocket ID client-ID charset `[a-zA-Z0-9._-]{2,128}`); group restriction explicitly `false` (API default; the UI defaults to `true` — Setup must be explicit); `PUT` api-access with permission UUIDs resolved from keys; publish Component-owned bindings under `~/.config/platform/workloads/<basename>/identity/` (not Binding remaps) — resource server: issuer, JWKS URL, `aud`; client: issuer, `client_id`, callback URLs, `resource`, `scope` (gathered permission keys only — standard OIDC scopes `openid`, `profile`, `email`, `groups`, `offline_access` are engine-provided on every client and not gathered or published by Setup). Intent **stop** unpublishes that binding and **leaves** Identity interior records (minting while the Workload is down is accepted). Omit Provides `permissions` (still Bound as a site), omit the client Declaration, Binding FQDN gone, or **Orphan Reap**: delete the corresponding Pocket ID API and/or OIDC client. Tokens already minted keep old `scope` strings until `exp`; delete does not revoke. Identity admin API material is Component admin material (not Environment Configuration). Slot bodies follow Database (ADR-0049 / ADR-0043): fulfillment/publish prefer `pre-workloads`; orphan cleanup in `post-workloads`.

**Amends:** ADR-0053 (Provides gains `permissions` and `oidc_callback`; Requires gains `identity` and optional client `permissions`; Binding: resource server exactly one FQDN); ADR-0040 / ADR-0043 (Identity is a further Declaration-fulfilling Component; Environment-authored issuer hostname beside Domain assignment); ADR-0034 (Service Network stays token-free; this story is public Bound APIs and SPAs only); ADR-0052 (Edge is not the JWT gate).

**Rejected:** Edge JWT verification (option 3); Hydra / Dex as this Identity Provider; inferring a resource server from Bound Routes; one Pocket ID API per alias FQDN; per-key or `*` permission Binding; clients named on the resource-server Artifact; globally unique keys without Binding FQDN on the RS; delete catalog/client on Intent **stop**; surgical permission HTTP (Pocket ID only offers full replace-by-key); CIMD or Pocket ID UI as v1 client registration; logout callback gather; user groups; Requires boolean `oidc`; convention issuer hostname (in `domains.json` or inferred); Identity as a Workload; Identity publishing Routes through the Workload Route channel (Components should not fake being Workloads — ADR-0040); magic `/callback` path; client secrets / `client_credentials` for Service Network; gather-time token revocation.
