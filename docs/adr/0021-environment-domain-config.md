# Environment Domain assignment lives under environments/

Which Domains an Environment owns is declared in committed `environments/<cloud-slug>/domains.json` (Environment tree; file = config — ADR-0033). The Stack loads that file from the current workspace’s cloud slug (`default` → `test`); missing file means zero Domains. No `TF_VAR_domains`, no per-Environment `-var-file` — workspace / `--env` is enough for bare CLI and operator scripts. An apex belongs in at most one Environment’s file; provider collisions fail closed. Narrowing the file (drop apex or A label) does not destroy on Apply — Durable `prevent_destroy` fails closed; widening Applies normally. Registrar NS stays out of band. See [ADR-0020](0020-domain-durable.md) for the Durable itself; runbooks cover add/import. Layout: [ADR-0033](0033-environment-first-repo-layout.md).

**Internal override (not an operator surface):** if `environments/<cloud-slug>/domains.override.json` exists, every Domain-assignment reader uses that file **instead of** `domains.json` (full replace, not a merge). The file is gitignored; Lifecycle Tests may write a derived assignment for additive fixtures and must remove it before returning the Environment to committed-only Apply. Not documented in operator runbooks. Paths are under the active **Environments root** (repo `environments/` by default; optional Operator Configuration relocation — ADR-0051).

**Considered:** Shared `*.auto.tfvars` (cross-Environment footgun); per-env `-var-file` (extra arg every raw CLI invoke); shell-bridged `TF_VAR_domains_<slug>`; single map file of all Environments; `-var=environment` to select the file (duplicates workspace / ADR-0019). Rejected. Path under `config/environments/` superseded by ADR-0033.
