# Component Setup and Host Volume layout

Public Hosts get Fabric then Components only **after** Initial Host Provisioning: IHP produces **Substrate** (engine, Platform User, port floor, Host Volume mount) and does not run Fabric Setup, Component Setup, or install Workloads — putting Setup inside cloud-init was rejected because SSH/copy is unsafe mid-IHP and user_data churn would recreate the Host for every change. Instead, operator-side `internals/ensure-fabric.sh` then `internals/ensure-components.sh` each wait for IHP Done (Substrate), scp/tar-copy their trees onto the Host Volume as root (in-place sync so live bind mounts stay valid), chown to the Platform User, and run **Fabric Setup** (Service Network) or **Component Setup** (Edge and Database) respectively — Host logs use that vocabulary. Component Setup Host contract is `pre-workloads.sh` + `post-workloads.sh` (not a single `setup.sh`); `ensure-components` takes a mandatory slot and Deploy invokes both (ADR-0043). Success means each Setup leaves its target **in the correct state** (header contract on each Setup script). Workload Setup (thin Manifest + Source + authored units; ADR-0011 / ADR-0014 / ADR-0017 / ADR-0022 / ADR-0024 / ADR-0053) and **Orphan Reap** are composed by **Deploy** (`ensure.sh`), not by ensure-fabric / ensure-components; neither writes Edge Route interior. ensure-components also stages the Domain-derived ACME FQDN list and Database admin credentials for Component Setup (ADR-0023 / ADR-0028 / ADR-0049). Edge Component Setup gathers Intent-**run** Route Declarations and installs on-demand ACME (ADR-0015 / ADR-0040); Database Component Setup gathers Requires `database` claims (ADR-0049).

**Host Volume layout:** mount root `/host-volume` stays root-owned; everything under it is Platform User–owned. Owner trees at the mount root (no `internals/` prefix, no top-level `data/`): `fabric/` (Service Network — Fabric Setup), `components/edge/` and `components/database/` (Component SoT; Edge includes `nginx.conf` and `domain-template.conf`), Mirrored `workloads/<basename>/`, and `host-scripts/` (Host-executable helpers + `lib/`, sourced by Setup — not a Component). Workloads and Components may hold nested **Persist** (`persist/`) for bytes that must survive Mirror/ensure; Edge Persist holds fulfilled `routes/`, Domain fronts `domains/`, `certs/`, and ACME HTTP-01 webroot; Database Persist holds interior data; Component Setup **handoff** lives at `components/handoff/`. Authored units live in one `systemd/` bag per owner (ADR-0054 / ADR-0034); Quadlet install is a kind-prefixed directory symlink farm so `Volume=../persist/…` resolves on Host Volume; native units copy into user systemd. Edge Component Setup ensures Edge Persist directories exist, gathers Route Declarations into Persist `routes/`, and never deletes Domain-front files it does not own. Durable source on the volume lets Fabric/Component Setup re-run after Host rebuild or Park→Apply without relying on IHP; Teardown removes the volume with the Stack (ADR-0025).

**Rejected:** Setup inside IHP; rsync; operator script named apply/provision (Stack apply / IHP collision); root-owned owner trees (blocks rootless binds); certs under replaceable SoT (certs belong in Persist); wiping runtime routes on ensure; treating Workloads as Components; treating Service Network as a Component peer of Edge; dual-read of retired `components/` + `components_data/` or `internals/` + top-level `data/` Host Volume layouts (ADR-0018 / ADR-0054).

**Amended by ADR-0054 / #215 / #216 / #218:** `/host-volume` + nested Persist + unified `systemd/` + relative Persist binds.
