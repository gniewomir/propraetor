# Edge owns Forwarded client identity (overwrite, no prior hop)

Edge is the sole public HTTP/HTTPS ingress. On every request it proxies to a Workload it owns **Forwarded client identity**: hop headers that describe the public client, always **overwritten** from the public TCP peer and request scheme/host — never left as client-supplied values and never appended for a trusted prior hop (no CDN/WAF in the Host shape). The set is `Host`, `X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto`, `X-Forwarded-Host`, and RFC 7239 `Forwarded` (`for=…;proto=…;host=…`, with IPv6 `for=` quoted). Soft use by Workloads (logging, redirects, URL generation); not hop authentication of Edge, and not a claim that the same headers are authentic on Service Network traffic that bypasses Edge. SoT is the Edge `http` block in Component `nginx.conf`. An operator Route that sets any `proxy_set_header` clears nginx inheritance for that `location` — treated as intentional override, not Setup-enforced.

**Rejected:** `$proxy_add_x_forwarded_for` / append-to-inbound `Forwarded` (implies a trusted hop in front of Edge); Host-wide “headers are always authentic”; Setup fail-closed on Route `proxy_set_header`; `by=` dial-name in `Forwarded` before Edge has a reserved Service Network identity.
