# Component Setup pre-workloads and post-workloads slots

Kind order on **Deploy** (Components before Workloads) is not the full readiness graph: Edge Route fulfillment embeds Workload Service Network identity that exists only after **Workload Setup**. A single mid-ladder Component Setup that gathers and loads those Routes leaves Edge unhealthy on cold bring-up; docs already expected a post-Workload Edge refresh (ADR-0022) that `ensure.sh` never ran. Propraetor keeps one kind — **Component Setup** — and makes the Deploy double-invoke explicit: every Component supplies Host scripts `pre-workloads.sh` and `post-workloads.sh`; `ensure-components` takes a mandatory positional `pre-workloads|post-workloads` (ADR-0039); **Deploy** runs `pre-workloads` after Orphan Reap and `post-workloads` after Workload Setup; standalone “Components correct” runs both in order — no `full` mode. Slot names are Deploy-relative (when), not semantic claims about what a Component must do in each; script bodies are Component-owned. Workload Setup and Orphan Reap do not invoke Component Setup — the caller composes `post-workloads` when Declarations may have changed outside Deploy. Partial Deploy failure: re-run Deploy (or caller-composed cogs); no dedicated half-Edge heal product.

**Edge slot bodies:** `pre-workloads` — cold: clear fulfilled Workload Routes, start with Domain fronts, ACME; warm: reconcile files only, no front-door reload/restart (including ACME must not bounce the door). `post-workloads` — gather Intent-**run** Routes, validate (fail closed), reload if up / start if down, ACME as needed, hard front-door wait. Missing upstream after a removed Workload is request-time failure (Edge stays up), not Setup failure. **Database** slot bodies are Component-owned (ADR-0049): fulfillment/publish prefer `pre-workloads`; orphan cleanup in `post-workloads`.

**Amends:** ADR-0041 (Deploy ladder gains a second Component Setup slot after Workload Setup; Orphan Reap still precedes `pre-workloads` so gather does not fulfill orphans); ADR-0022 / ADR-0040 (refresh after Workload Setup / Orphan Reap is Component Setup `post-workloads`, composed by Deploy or the caller — not an implicit second monolithic `setup.sh`); ADR-0010 (Component Setup Host contract is the two scripts, not a single `setup.sh`).

**Rejected:** Deferred DNS in every Route as the primary fix (operator contract change; still needs gather refresh); Workloads before Components on the ladder (breaks cold ACME/:80); only Edge special-cased in Deploy (bitrots when a second Declaration-fulfilling Component appears); semantic phase names (`platform` / `declarations`) as Deploy vocabulary; a `full` ensure-components mode; auto-invoking `post-workloads` from each `ensure-workload` / Orphan Reap (N front-door disruptions; blurs fulfillment ownership); inferring pre vs post from Host state; transactional rollback of Route files after a failed mid-Deploy.

**Amended by ADR-0054 / #217:** Deploy ladder has no Purge step; `post-workloads` follows Workload Setup directly.
