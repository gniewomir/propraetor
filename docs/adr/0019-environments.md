# Environments: namespaced Stack instances under one account

Lifecycle Tests and future parallel use needed isolation under a **single** provider account and token. A **Provider Credential** cannot separate blast radius; an **Environment** does: a namespaced instance of a Stack with its own State and its own account-unique cloud names (Cloud Project, Host, Host Volume, Domain, tags, Firewall). Host root login is not an account-unique Stack name — see [ADR-0037](0037-host-login-via-ihp-not-account-ssh-key.md). Slugs are open-ended (`test`, `prod`, `dev`, `staging`, … — no fixed enum). A `prod` Environment is optional and created only when needed. Distinct from the Cloud Project metadata `environment` field (Production / Staging / …), which is billing/UI labeling only.

**Default-safe operator CLI (general rule):** Every Propraetor operator entrypoint — Apply, Park, Teardown, Acceptance Tests, Host-facing helpers that read Stack outputs (e.g. ensure-components, workload setup, purge, ssh), and any later root CLI — accepts an Environment parameter and is **safe by default**: with no Environment flag it selects the **test** Environment (Terraform workspace `default`). Targeting any other Environment always requires an **explicit** `--env <slug>` on that invocation. No entrypoint is exempt from declaring which Environment it uses.

**Lifecycle Tests exception:** Lifecycle is **test Environment only** (fail closed on any other `--env`, including aliases other than `test`/`default`). Destructive Park / Teardown suites must not be pointed at non-test Environments by a flag alone — ADR-0042.

**Naming:** Every Environment uses the same derivation rule — account-unique names are prefixed with the Environment slug (e.g. `propraetor-<slug>-…`). No bare-name exception for `prod`. All such names derive from one Stack-local naming map keyed by slug; provider `name` literals elsewhere are rejected. Reserved IP has no name; isolation is via State ownership.

**State:** Terraform workspace per Environment. Workspace `default` **is** the **test** Environment (so bare `terraform` in the Stack dir touches test, not prod). Other Environments use a workspace named exactly as their slug (`prod`, `dev`, …). Cloud name slug for workspace `default` is `test` (not `default`). Prefixes follow the current workspace (`default` → `test`); we do not require a separate `-var=environment` for day-to-day raw Terraform.

**`--env` mapping:** Operator scripts select workspace from the flag: no flag, `--env default`, and `--env test` all select workspace `default` (test); only `test`↔`default` is aliased. Any other slug selects a workspace of that name (created if needed). For entrypoints that allow non-test Environments, `--env prod` (or any other slug) is sufficient intentional opt-in; existing Park/Teardown typed confirms stay as today — no extra prod-only gate for now. Scripts are stricter than raw Terraform: they always select the resolved workspace for the invocation rather than trusting whatever workspace happened to be current.

**Cutover note:** Current State is already the test Stack and stays in workspace `default`. Introducing Environments means renaming today’s bare cloud names onto the `test` prefix under the uniform rule — not migrating State into a `prod` workspace.

**Amended by ADR-0042:** Lifecycle Tests are hard-bound to the **test** Environment (fail closed); Acceptance non-**test** is diagnostic and confirm-gated.

**Considered:** Required `-var=environment` with no default (forces naming every raw Apply; fights “unspecified → test”); Terraform `default` workspace overloaded as prod; `prod` keeps bare names; closed enum of Environment slugs; Lifecycle Tests sharing Acceptance’s “any `--env` allowed” rule (rejected later — ADR-0042: Lifecycle stays test-only); scripts only as strict as raw workspace selection; separate State-path scheme instead of workspaces; separate DO accounts for isolation. Rejected for friction, footguns, or premature complexity under one account.
